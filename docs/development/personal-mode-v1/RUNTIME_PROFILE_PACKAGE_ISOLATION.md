# Runtime and package isolation

Rust accepts only `REQUESTED_SYNTHETIC` or `REQUESTED_PERSONAL` from trusted launch context, not renderer input. It starts distinct profile-specific sidecars. Synthetic receives only its fixed Synthetic root and may receive `OPENAI_API_KEY` when configured. Personal receives only its fixed Personal root, repository gate root, and no provider credential; the admission-only Personal sidecar receives no vault root until `evaluate_evaluation()` returns current OPEN.

Personal command allowlist: lock/unlock; capture/session/turn/list/get/search; exploration/formulation/correction; delete; backup/restore/recovery/export. It excludes actions/outcomes, archive, AI, Longitudinal, Review/Return/Follow-up, import/parser/render, scoring, handoff and blobs. The Python dispatcher repeats the effective-profile check; a direct backend call has no bypass. Every denial is content-free.

`PERSONAL_PACKAGE_INVENTORY_RULES`: build a profile-specific Personal PyInstaller sidecar from a Personal entrypoint with an explicit allowlist; it must contain no importer/parser/quarantine/document-render modules or associated commands. Provider code may exist in the repository but Personal package contains no provider adapter/transport and receives no credential. Deterministic package test inspects frozen modulegraph, executable module inventory and Rust command table; it fails if a forbidden module/command/path or `OPENAI_API_KEY` forwarding appears. Synthetic package behavior stays accepted and independent.
