# Personal lifecycle: backup, restore, export, deletion, and rotation

All Personal operations are behind `PERSONAL_ADMISSION_GUARD`; a closed/expired gate cannot decrypt, open, search, restore, export, or delete Personal content. Backups are Personal-root-only and carry `PMV1-RECOVERY-BOOTSTRAP-V1`, authenticated encrypted payload, and recorded `key_version`. A backup made with N remains recoverable after active rotation to N+1 only through the immutable retained N envelope and a recovery secret. N+1 backups use the active N+1 envelope. Neither may alter an active vault during validation.

Restore first verifies bounded bootstrap/authentication, then decrypts into a private same-root staging directory, opens with the recorded historical Kdb, verifies schema/inventory/semantic values, `integrity_check`, `foreign_key_check`, search rebuild, and reopen. It requires an explicit owner activation after successful isolation; restoring N must not corrupt or overwrite active N+1. Historical bootstrap/header inspection may be content-free before OPEN, but any secret unwrap/payload/staging access requires the guard.

Rotation is `PMV1-ROTATION-ISOLATED-REENCRYPTION-V1`, never in-place rekey. During a journaled transition normal writes are disabled. After verified DB N+1 activation, it publishes and reopen-verifies immutable retained N protected material and separately authenticated `prepared_for_retention` lifecycle metadata before active-envelope promotion. Only then may N+1 become active; metadata changes atomically to `retained_for_read` with N's actual retirement time. Thus the last durable protected VMK(N) survives promotion and can authenticate the N-authenticated stale journal. The full journal/state/publication protocol and recovery behavior are normative in `PERSONAL_KEY_RECOVERY_DESIGN.md`.

Export derives only the active current Kexport, is encrypted and backend-enforced `audience=OWNER_ONLY`; historical exports are external copies and are not re-encrypted/rewritten by rotation. Deletion removes Personal session roots and their turns/exploration/formulations/history/search projections only in the Personal root; it states the limits of previous backup/export copies. Deletion/backup retention updates the maximum `retained_for_read_until` for each historical key. A key is destroyed only after every backup using it is expired/deleted and no active DB, journal, staging recovery, or restore depends on it; destruction produces a content-free receipt and never a permanent growing keyring.
