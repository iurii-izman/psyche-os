## Implemented

Smallest deterministic professional handoff slice for the frozen profile
`personal_informational_consultation_handoff`
(audience `mental_health_professional`, purpose
`professional_consultation_handoff`):

- **Profile/intended use** — typed profile with a frozen intended-use boundary;
  unresolved legal/privacy/clinical-safety/human-factors approvals are recorded
  truthfully as `PENDING_QUALIFIED_REVIEW`, never invented or waived.
- **Explicit selection** — final report membership comes only from explicitly
  selected canonical `(record_id, version_id)` pairs; exclusions are
  report-only transformations; E09 is never selection authority.
- **Provenance/epistemic status** — canonical kinds and typed status columns
  (source / verbatim report / observation / assertion + modality / claim type +
  status / unknown) survive into the report and manifest; no new interpretation.
- **Linked counterevidence** — selected records with canonical
  contradiction/counterevidence relations (contradiction-set membership,
  contradicts-family evidence links, or a claim directly naming a
  `contradiction_set_id`) automatically include the linked material, marked as
  `materially_linked_counterevidence`.
- **Redaction/exclusion** — previewed report transformations bound to exact
  canonical versions; canonical data is never mutated.
- **Safe deterministic output** — deterministic UTF-8 Markdown + deterministic
  JSON manifest; hostile HTML/Markdown/URL content is escaped to inert literal
  text; manifest carries identity/provenance metadata, never content excerpts.
- **Report identity** — stable typed `report_id`, version, audience, purpose,
  canonical cutoff, selected/excluded ids, transformation identity,
  builder/config version, policy identity, report digest, disclosure state.
- **Preview + authorization** — exact local preview (audience, purpose,
  selection, sections, exclusions/redactions, counterevidence, uncertainty
  count, output format, authorized destination, retention semantics,
  external-copy limitation, builder/config/policy identity, pending-review
  items) bound by digest to a service-minted, single-use, non-transferable
  authorization; fabricated/replayed/cross-service capabilities are rejected.
  The single-use `disclose()` capability covers the complete authorized
  disclosure action (revalidate → build → write to the authorized destination →
  receipt).
- **TOCTOU** — immediately before generation the preview is recomputed from
  current canonical state and compared to the authorized digest; any material
  change (source/version, policy, eligibility, transformations) invalidates the
  authorization; no silent reuse.
- **External-copy truthfulness** — the limitation is visible in preview,
  report and receipt; corrections/deletions never claim to update external
  copies.
- **Content-free receipt/logging** — bounded disclosure receipt and `repr`
  surfaces carry no report text, excerpts, paths, unredacted values or
  plaintext content hashes.
- **Filesystem boundary** — narrow outer `ReportFileWriter` adapter validates
  the destination (no traversal, no silent overwrite, links/non-regular
  targets rejected) and writes atomically; no upload or network path.
- **AI independence** — the E10 core makes no model/provider/network call.

## Policy semantics (authority-backed)

- **Missing policy fails closed.** PS-01
  (`docs/architecture/PRIVACY_SECURITY_MODEL.md`: "Missing or contradictory
  policy fails closed") and the Master Spec §409 ("Missing/ambiguous policy
  fails closed") are the controlling authority for the E10 disclosure gate. E10
  therefore returns `POLICY_MISSING` when no active `data_policies` row exists,
  and `POLICY_BLOCKED` when any active policy is outside the local/no-cloud,
  audience-bounded export profile. The weaker E09 local-retrieval check
  (universal quantification over active policies, allow-by-absence) governs a
  different boundary and is not authority for disclosure; the threat model
  also requires the core to "fail closed on unknown policy".
- **`data_policies.purpose` is not an export-gate input.** The accepted
  privacy model defines export controls as "allow / redact / block / ask, **by
  audience**" (`docs/architecture/PRIVACY_SECURITY_MODEL.md`); the `purpose`
  field belongs to the local/cloud policy ("named allowed providers/purposes"),
  i.e. the E07 LLM-disclosure path, not the E10 local export gate. Enforcing
  `purpose` in the E10 gate would be invented policy semantics; current
  behavior (fail closed on processing location, cloud policy, export rule and
  export audience) is preserved.

## Disclosure transaction boundary (F7)

The single-use authorization now binds the complete disclosure action per
PS-03 ("the user sees destination, purpose, provider policy snapshot, record
categories/IDs, redaction/transformation and expected retention before
authorization; a request-scoped capability expires after the call"):

- the exact export `destination` is chosen before authorization and is visible
  on the preview; it is bound into the preview digest but never enters the
  report bytes;
- the preview also carries truthful export-retention semantics
  (`EXPORT_RETENTION_NOTE`: the file is written only to the authorized
  destination; the system keeps no copy and makes no deletion/update
  guarantee);
- `disclose()` is the complete authorized action: revalidation → deterministic
  report construction → write to the authorized destination → content-free
  receipt; the capability is consumed by the disclosure and invalidated on any
  failure, so it cannot be replayed to another destination.

## Known limitations

- Missing/ambiguous policy fails closed (`POLICY_MISSING`); any active policy
  outside the local/no-cloud, audience-bounded export profile is
  `POLICY_BLOCKED`. `data_policies.purpose` is not an export-gate input by
  accepted privacy-model authority ("export … by audience"). See "Policy
  semantics" above.
- The extractor covers the six canonical semantic text tables (source
  artifacts, reports, observations, assertions, claims, unknowns). E05
  measurements and E06 experiment-result tables are not separately indexed;
  their derived/measurement distinctions are surfaced where represented in the
  semantic tables (e.g., `device_observation`, claim origin/status).
- Revalidation is performed immediately before the disclosure write against the
  current connection; concurrent writers between revalidation and the write are
  out of scope for the local single-connection synthetic profile.
- The filesystem writer does not enforce operating-system access-control
  policy beyond the base-directory and regular-file checks; it is an outer
  adapter, not an authorization boundary. Real symlink rejection is verified
  only where the OS permits symlink creation; the link-rejection path-validation
  logic has deterministic coverage on all platforms.
