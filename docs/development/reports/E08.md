## Implemented

- Exactly one repository-owned profile, `utf8-plain-text-v1`, accepts a standalone
  regular file through the outer filesystem adapter. It uses strict UTF-8, records
  one optional leading BOM, preserves Unicode and CR/LF/CRLF, and has no proprietary
  format-rights or runtime parser dependency. The `imports` module owner maintains
  this profile.
- The only path-bearing component performs non-following identity inspection,
  rejects non-regular files, links and Windows reparse points, compares pre-open,
  opened and post-read file identity, and reads at most one unit beyond the byte
  budget. Application-owned quarantine uses an opaque random identity and a keyed
  protected byte reference; caller names and paths do not enter parser, domain,
  canonical records, events or errors.
- Exact frozen limits are 1,048,576 original bytes, 1,000,000 decoded code points,
  4,096 physical lines, 16,384 code points per physical-line content and 4,096
  non-empty line segments. All limits are enforced during bounded read/strict
  incremental decoding or line construction; no partial candidate or canonical
  commit is returned.
- `psyche-os-stdlib-utf8` version `1.0.0` is an injected, in-process,
  standard-library-only parser. It receives bounded bytes, the frozen profile and
  opaque provenance metadata only. It has no path, database, vault/key, logger,
  provider, network, tool or canonical write handle.
- Immutable candidate identity binds opaque source/quarantine/version identities,
  protected bytes, byte/BOM/encoding/profile/parser/config identities, counts,
  transformations, exact text segments, untrusted state and policy lineage.
- Every non-empty segment records physical line, decoded character range, original
  absolute byte range, exact source version and original newline kind. Tests recover
  hostile Unicode segments directly from their original byte ranges.
- Local preview binds exact candidate, mappings, transformations, policy, duplicate
  decision and optional correction target. Samples are bounded and HTML-escaped;
  Markdown and URLs are inert. Consent is an object-identity capability minted by
  one service instance, exact-preview-bound and single-use.
- Immediately before commit the service rechecks quarantine integrity and state,
  outer source identity, exact protected bytes, profile, parser/config, candidate,
  preview, consent and policy lineage. It fails closed rather than rebuilding or
  approving changed input.
- Application-owned canonical mapping creates only an attributed verbatim report or
  a review-needed assertion proposal. Immutable source bytes, exact source segments,
  explicit redaction/exclusion derivations and mapped records remain separate.
  Imported instruction-shaped text never becomes policy, fact or authority.
- Duplicate protected bytes require an explicit reject/import-separately decision.
  Correction creates a new immutable source/version, marks the prior version
  superseded without rewriting it and records an explicit `corrects` relation.
- Deletion derives closure over actual source/segment/transformation/record/relation
  parents. It deletes exclusive descendants and quarantine bytes, invalidates and
  clears mixed descendants, preserves unrelated sources, rejects stale plans and
  rolls back injected storage faults. Verification covers canonical query, export
  and raw-source absence. Receipts are content/hash-free.
- Operational events and typed exceptions contain allowlisted opaque identity,
  component/profile/status and typed reason only. Source content, excerpts,
  filenames, full paths, parser dumps and stable raw digests are absent. E08 has no
  E07/provider import and functions without any AI, network or tool port.
- The bounded provenance fields preserve future attributed-external-source,
  untrusted-content and policy-lineage distinctions without implementing a
  psychologist workflow, retrieval, context building or E09.
