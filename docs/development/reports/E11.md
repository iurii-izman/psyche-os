## Implemented

- Added strict JSON Schemas and deterministic, side-effect-free evaluation for
  one exact candidate's profile, source/build/platform, lock/SBOM/artifact,
  typed machine-proof, review, expiry, residual-risk, seal, successor, and
  human-attestation bindings.
- A DRAFT never supports `OPEN`; a SEALED payload must match its digest; changed
  invalidated facts require a distinct successor; missing/expired/mismatched
  evidence, reviews, reproduction, required review classes, exact exclusion
  proof, residual-risk disposition, or human attestation all return `CLOSED`.
- `PROVED_FOR_CANDIDATE` accepts only an admissible, passing deterministic
  validator-result artifact whose raw contents match the exact candidate and
  RDG mapping. A release manifest or generic hashed file cannot prove a control.
- The profile definition is verified from `profile_source_commit` using Git
  object bytes and must be in the candidate lineage; the profile-definition
  commit need not equal the candidate source commit.
- Added one repository-owned synthetic DRAFT release manifest/evaluation for
  the canonical pre-E11 source. It truthfully remains incomplete and `CLOSED`.
  No human attestation or authorized `OPEN` decision exists.
- The research validator now has no broad synthetic-token exception: every
  secret-shaped value remains in scope for detection.

## Constitutional / security notes

`REAL_DATA_GATE` remains `CLOSED`. The evaluator does not modify application
state, manufacture evidence, seal a file in place, or create a human decision.
Coding-model and wrong-digest attestation paths are tested as closed failures.
The only `OPEN` path is an isolated synthetic oracle with verified typed proof,
valid exclusions, a valid seal, and a bound `HUMAN_REPOSITORY_OWNER` attestation.
