# Критический аудит PSYCHE OS v1.0

**Аудируемый документ:** `docs/specs/PSYCHE_OS_MASTER_SPEC_v1.0_2026-08-10.md`  
**Роль v1:** историческая гипотеза, не источник научной истины  
**Статус аудита:** baseline complete; решения подлежат финальной сверке с `SOURCE_REGISTRY.yaml`

## Метод

Решения используют классы `KEEP`, `KEEP_AND_STRENGTHEN`, `MODIFY`, `MERGE`, `REMOVE`, `DEFER`, `RESEARCH_REQUIRED`, `REPLACE_WITH_BETTER_MODEL`. Класс означает судьбу идеи, а не оценку качества текста. Для каждого крупного элемента зафиксированы польза, уязвимость, требуемая опора, итоговое разрешение и остаточный риск.

## Итог baseline-аудита

v1 необычно сильна в эпистемических ограничениях: она уже отделяет source от interpretation, memory от fact, screening от diagnosis, correlation от causation и требует provenance, contradictions, unknowns, deletion и provider independence. Главная проблема не в направлении, а в том, что многие хорошие принципы пока существуют как декларации, несколько разных сущностей смешаны в одну «evidence graph», privacy сведена к одной шкале, bitemporality описана слишком узко, а научные и технические утверждения почти не имеют проверяемого реестра источников. v2 должна сохранить философию скептической модели, но заменить широкую vision‑онтологию точными контрактами, gate‑ами и проверяемыми состояниями.

| A-22 | Are passive sensing features clinically useful because they are measurable? | Surveillance and pseudoscience risk | No; most are deferred unless a concrete validated decision use exists |

| A-24 | Can model output safely create canonical facts after schema validation? | Data integrity | No; schema validity is not evidentiary validity; outputs remain derived proposals with lineage |
| A-25 | Can prompt rules stop prompt injection? | Imported archive safety | No; need isolation, least privilege, deterministic policy and no direct actions |

## What survives from v1

The durable core is: local-first canonical evidence; raw/derived separation; provenance; explicit uncertainty, contradiction and unknown; memory humility; deterministic/versioned psychometrics; state/trait/context separation; functioning and confound checks; typed claim thresholds; falsification and alternatives; provider-independent data; cloud minimization and `NEVER_CLOUD`; hard deletion; versioned model snapshots; no real data before a security gate.

## What v2 must materially replace

The main replacements are: product terminology, one-dimensional privacy classes, single confidence fields, event-as-fact modeling, the linear evidence ladder, the exhaustive human ontology claim, the fixed daily/17-wave intake, full event-sourcing implications, premature schema/table inventory, screen-heavy UI, agent-role proliferation, unverified stack inheritance and the original F0 prompt.
